# Examiner Co-Pilot

A supervisory workbench that compares credit-card disclosures (KFS, T&C, Rewards, Fees Schedule, and adverts) against an examiner-supplied, versioned rulebook. Agents propose; examiners decide. The workspace holds production data only (no demo data).

## Run & Operate

- Web app (Next.js 15 App Router): workflow `artifacts/examiner-copilot: web` — served at `/`
- API (Express 5): workflow `artifacts/api-server: API Server` — served at `/api`
- `pnpm --filter @workspace/api-spec run codegen` — regenerate hooks + zod from `lib/api-spec/openapi.yaml`
- `pnpm --filter @workspace/db run push` — push DB schema (dev only)
- `pnpm --filter @workspace/api-server test` — Vitest unit tests (audit hash chain, LLM adapter, assessment decisions, injection handling, run limits)
- `pnpm run typecheck` — full typecheck
- Secrets: `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` (needed from Milestone 2; app shows a clear error without them)

## Stack

- pnpm workspaces, Node 24, TypeScript 5.9
- Frontend: Next.js 15 (App Router), Tailwind v4 via `@tailwindcss/postcss`, shadcn/ui, React Query hooks generated by Orval
- API: Express 5 + zod 4 (generated), PostgreSQL + Drizzle ORM
- Tests: Vitest 4 (Vitest 3 cannot install here: its `tinypool` dependency is blocked by the package firewall)

- DB schema: `lib/db/src/schema/` (full planned data model; every business table has `dataset`)
- Dataset scoping: `artifacts/api-server/src/lib/dataset.ts`

- PDF checks and page-by-page extraction (no OCR; pages with little text are gaps): `artifacts/api-server/src/lib/pdf.ts`
- Rule-based upload suggestions (type, language, bank, product, each with a reason): `artifacts/api-server/src/lib/suggest.ts`
- Rulebook .xlsx/.csv import (column mapping, row validation; unmapped columns are kept as rule `details` and passed to the Rule agent; title optional, derived from rule text): `artifacts/api-server/src/lib/rulebook-import.ts`
- Fictional test fixtures (3 banks, 12 rules, 12 PDFs), used only by unit tests: `artifacts/api-server/src/__tests__/fixtures/`
- Banks in scope: ADCB, ADIB, CBD, Mashreq, for credit card product documents only. Official logos are in `artifacts/examiner-copilot/public/banks/` and matched to a bank by name (English or Arabic, short or full) in `artifacts/api-server/src/lib/bank-logos.ts`, so a bank re-added under the same name gets its logo. On API startup, `ensureScopeBanks` adds the four banks when the library is empty (so the published app gets them; audited as "Setup script"); once any bank exists it does nothing.
- Preview auto sign-in: in development only (NODE_ENV=development), a request with no Clerk session acts as the earliest senior examiner, and the web app skips the welcome screen. Production always requires sign-in. Set `PREVIEW_AUTO_SIGNIN=false` to test the real sign-in flow in the preview.
- Empty rulebook template download: `GET /api/rulebooks/template.xlsx`
- Voice components (bank / tool / examiner) and StatusPill: `artifacts/examiner-copilot/src/components/voice/`

## Architecture decisions

- Next.js is the UI only; all server logic lives in the shared Express API at `/api` (the proxy routes `/api` there, so Next route handlers must not use `/api`).
- Every business table has a `dataset` column; the workspace is always `live`. On API startup `removeDemoData()` deletes any leftover `demo` rows in one transaction and sets `app_state` to live (idempotent). There is no demo loader.
- Audit log is append-only with a per-dataset sha256 hash chain, so purging demo data leaves the live chain intact.
- Sign-in: Replit-managed Clerk (email/password, Google). Every /api route except /healthz requires a session (`requireUser` in `lib/auth.ts`); the local `users` table holds the assigned role. The first person to sign in (per environment) becomes Senior examiner, everyone after starts as Viewer; senior examiners change roles in Settings → People, and the last senior examiner cannot be demoted.
- Write permission comes from the signed-in person's stored role, never from the request body. The actor ("Name <email>") is taken from request context (AsyncLocalStorage) and stored on audit events and decisions; it is part of the audit hash only when present.
- Next.js reads the Clerk key through `next.config.mjs` env (`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` from `CLERK_PUBLISHABLE_KEY`, proxy URL from `VITE_CLERK_PROXY_URL`). Sign-in pages live at `/sign-in` and `/sign-up` catch-all routes; signed-out visitors see a welcome screen.
- Exactly one active rulebook version per dataset; activating one retires the previous one. Retired versions cannot be reactivated.
- Duplicate uploads are detected by sha256 within the dataset (409 with `existingId`).
- The model adapter throws a clear `LlmError` on any missing config or provider failure; it never returns fabricated content.

## Product

Milestones: M0 foundations (done) → M1 upload and library (done) → M2 assess (done) → M3 review and decide (done) → M4 notices → M5 overview and assurance → M6 market and what-if → M7 hardening.

## User preferences

- Stack: Next.js (user chose to keep it over the default Vite).
- Push to GitHub at the end of each milestone, after tests pass.
- No demo data; the user wants a clean workspace for production data. Keep the UI free of model names and filler text; the signed-in user menu sits at the bottom of the sidebar.
- Statuses: Compliant, Breach, Warning, Needs review, Not applicable; severity separate (Low/Medium/High).
- Roles: Examiner, Senior examiner, Viewer, assigned per person by a senior examiner. Viewer cannot change anything.
- 14 business days count from an examiner-entered reference date; day 1 is the next business day; weekend Sat–Sun.
- Disclosures PDF only; rulebook .xlsx or CSV (UTF-8). Rulebook check types include binary/subjective/calculation (judged by the Rule agent in batches of 12); document roles TC→tnc, SOFC→fees, ADVERT→advert.

- Model provider: OpenRouter. The key is stored as the secret `OPENAI_API_KEY` (`OPENROUTER_API_KEY` also accepted and wins if both exist). Model in env var `OPENROUTER_MODEL`, currently the free `nvidia/nemotron-3.5-super-vl:free` (user asked for a free model).

## Assessment runs (M2)
- Agents (Coordinator, Evidence, Consistency, Rule) only return JSON proposals; code in `lib/assess/` verifies every quote against stored page text and makes all numeric, cross-document, bilingual and readability decisions.
- A Compliant/Breach with no verified quote becomes Warning; an absence Breach is allowed only if every page was readable; the Consistency agent can downgrade a code-found difference to Needs review but never clear it.
- Each run is bounded (20 model calls, 250k tokens, 2 Coordinator rounds); one run at a time; a provider failure fails the run and writes no findings. Runs interrupted by a restart are marked failed at startup.
- Document text is wrapped as untrusted data; instruction-like passages raise an alert and are ignored.

## Ingestion agent
- Proposes document type, language, bank and product (first 2 pages) and rulebook column mappings (headers + 5 sample rows). Stored apart from the rule-based suggestion and compared with it (agrees/differs). Code drops any value whose quote is not found, any unknown bank/product id, a product from another bank, and any header not in the sheet or used twice.
- Document proposals run in the background after upload (one call at a time); the confirm dialog prefers the rule-based value and uses the agent's only to fill a gap. Mapping proposals are on request.

## Review and decide (M3)
- Queue = findings from the latest finished (complete or stopped) assessment per product; older assessments are readable but closed to decisions (409).
- Decisions are append-only; latest wins. Accept keeps the proposed status; Modify needs a different status and a note; Reject needs a note and stores no final status (no finding stands).
- Bulk accept covers only undecided, verified Compliant/Not applicable proposals of one assessment.

## Gotchas

- `lib/api-client-react/tsconfig.json` needs `dom.iterable` or codegen's typecheck fails on `Headers.entries()`.
- shadcn components under the App Router need `"use client"`.
- Publishing runs a dependency security scan that blocks on high/critical advisories. Patch transitive packages with `overrides` in `pnpm-workspace.yaml`. zod is on v4 (catalog) and orval's zod output is pinned to `version: 4`; keep them in step.

- `pkill -f dist/index.mjs` also kills the dev API server (dev runs the built bundle). Kill a test process by PID instead.
- Demo load only works on an empty demo dataset. To reload during development, delete the demo rows (documents, rulebooks, banks, stored_files, audit_log where dataset='demo') first.
- Arabic demo PDFs are pre-rendered (Chromium + Amiri font) and stored as base64; pdf-lib's standard fonts cannot render Arabic, and Noto Naskh extracts as garbled text.
- PDF text extraction strips control characters: Arabic ligatures can extract as NUL, which Postgres rejects.
- Arabic PDF text often comes out of reading order, so a bilingual 'difference' where the English figure also appears in the same Arabic quote is treated as a pairing error, not a breach.

- Free OpenRouter models are often rate-limited upstream (429), and reasoning models return empty content if `max_tokens` is too small. The Nemotron model needs ~10k max_tokens per agent call; 6k sometimes ran out before answering.
- Running `next build` into `.next` while the dev server runs breaks the preview. For local checks build with `NEXT_DIST_DIR=.next-check pnpm --filter @workspace/examiner-copilot run build`.
